漏洞名称：空字节截断漏洞 / 底层解析差异利用

1. 挑战概述
漏洞类别：不当的输入验证 / 路径遍历缺陷

挑战目标：利用 URL 编码中的空字符，绕过应用层的安全白名单校验，成功请求并读取受保护的系统文件。

2. 漏洞原理与机制

Poison Null Byte是一个极其经典的底层安全漏洞。它的本质是：高级 Web 编程语言与底层操作系统在处理字符串“终止符”时的逻辑不一致。
在前面通过%2500.md下载文件时其实就已经完成了这个挑战

1. 机制差异分析：
   - 在 Node.js或 PHP 的应用层代码中，字符串是以长度来标识边界的。因此，字符串 `test.bak%00.md` 被视为一个包含 11 个字符的完整字符串。应用层的 `endsWith('.md')` 校验器会认为它是一个合法的 Markdown 文件。
   - 然而，当这个字符串被传递给底层的文件系统 API时，C 语言使用空字节 /0 (即 0x00) 作为字符串的结束标志。
2. 击穿防线：应用层看到 `.md` 结尾，底层 C 库读取到 `%00` 时，直接丢弃后面的 `.md`，最终去磁盘中读取了真正的 `eastere.gg` 文件。

3. 实战危害与加固建议
实战危害展示：虽然在现代较高版本的运行环境中，底层已经对很多空字节注入进行了修补，但在实战护网中，我们依然能在很多老旧政企系统、嵌入式 Web 设备、或者某些自定义的 C/C++ 扩展模块中发现它的身影。黑客利用它可以轻易将“任意文件上传”转化为 RCE，或将普通的图片读取转化为任意源码泄露。

修复方案：
1. 框架层面的严格清洗：在 Web 请求进入核心业务逻辑之前，必须使用全局中间件或 WAF，强制过滤掉所有输入参数中的空字节（如正则表达式替换 `\0`、`%00`、`%2500`）。
2. 避免直接的文件路径拼接：绝不要将用户控制的输入直接作为参数传递给文件系统操作 API。应采用安全的映射机制（如根据数据库中的 FileID 去反查后端绝对路径），彻底切断外部参数对文件路径的物理影响。
