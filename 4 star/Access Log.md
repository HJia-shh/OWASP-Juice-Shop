漏洞名称：服务器访问日志泄露 / 安全配置错误

1. 挑战概述
漏洞类别：敏感数据暴露 / 安全配置错误

挑战目标：在没有任何前端链接指引的情况下，发现并访问系统底层生成的服务器 HTTP 访问日志文件。

2. 漏洞发现线索与复现过程

在情报收集阶段，目录爆破是红队必备的基础技能。很多开发者为了调试方便，会将日志目录放在 Web 根目录下，并错误地开启了目录浏览权限。

1. 由于前端页面没有任何指向日志的链接，我们需要使用自动化工具进行盲目探测。在 Kali终端，使用Web 目录字典对目标网站发起扫描：gobuster dir -u http://127.0.0.1:3000 -w /usr/share/wordlists/dirb/common.txt --exclude-length 75055

3. 实战危害与加固建议
实战危害展示：日志泄露是极度危险的安全配置错误。因为在 RESTful 架构中，很多敏感参是通过 GET 请求传输的。一旦 Access Log 被外网访问，黑客不仅能绘制出整个企业内网的 API 拓扑图，还能通过回溯历史日志，直接窃取其他管理员的活跃会话凭证，实现零交互的账号劫持。

修复方案：
1. 彻底关闭目录浏览权限：在 Web 服务器或 Node.js 应用网关层，必须全局禁用目录列表功能。任何试图访问没有默认主页的目录请求，都必须强制返回 403 Forbidden。
2. 日志文件脱离 Web 根目录：绝不能将任何日志文件、数据库备份文件存放在可通过 Web 路由直接访问的 public/ 目录及其子目录下。
3. 部署集中化日志管理体系：企业应废弃在应用节点本地存储并直接查看日志的落后做法。应通过 Filebeat/Logstash 将日志实时推送到内网隔离的 ELK（集群或阿里云 SLS 中，严格限制运维人员的查询权限，并对日志中的敏感 Token 和密码进行自动脱敏拦截。
