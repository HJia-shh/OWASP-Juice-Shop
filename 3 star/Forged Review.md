漏洞名称：伪造商品评价 / 越权写入

1. 挑战概述
漏洞类别：访问控制缺陷 / 不安全的直接对象引用

挑战目标：利用后端 API 盲目信任前端传参的缺陷，以其他用户的名义发表一篇商品评价。

2. 漏洞发现线索与复现过程

在电商系统的安全测试中，商品评价模块是业务逻辑漏洞的高发区。如果后端没有严格对齐“发帖人”与“当前会话凭证”，攻击者就可以任意篡改评价的归属者。


1. 在商品评价输入框中，随便写一段评价内容提交，同时使用burp suite抓包
2. 观察Request数据，包含了一个author。
3. 将内容改成其他账户即可，后端接收到该请求后，没有去比对 JWT Token 里的真实邮箱。

3. 实战危害与加固建议
实战危害展示：电商平台的信用体系建立在真实的商品评价之上。如果存在这种越权写入漏洞，黑客可以通过脚本批量冒充真实买家发布虚假好评，或者冒充竞争对手发布恶意差评。且黑客可以冒充“官方管理员”在评价区发布包含钓鱼链接的欺诈信息，直接损害平台声誉和用户财产。

修复方案：
1. 废弃前端身份传参：与“伪造反馈”漏洞的修复逻辑一样，涉及用户身份标识的字段绝对不能通过前端 HTTP 报文主体传递。
2. 服务端鉴权提取：当后端控制器处理“发表评价”的请求时，应当直接从 HTTP 头的 JWT Token中解析出当前用户的真实邮箱，并将其硬编码到准备插入数据库的实体对象中，彻底掐断客户端篡改归属人的可能性。
