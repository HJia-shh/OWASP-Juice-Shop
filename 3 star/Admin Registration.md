漏洞名称：越权注册管理员

1. 挑战概述
漏洞类别：业务逻辑缺陷
挑战目标：利用后端 API 缺乏字段过滤的缺陷，在正常的账号注册流程中，强行将自己的账号角色提升为系统管理员。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，如果后端使用 ORM 框架并直接将前端传来的 JSON 对象整体绑定到数据库模型上，就会产生批量赋值漏洞。攻击者可以在请求体中恶意添加原本不该由客户端控制的关键权限字段。

3. 实战危害与加固建议
实战危害展示：批量赋值是极其危险的业务逻辑漏洞。它允许攻击者在注册、修改个人资料或更新订单时，私自向后端传入未经验证的底层数据库字段（如 `Admin`, `role`, `balance`）。黑客可以借此瞬间将新注册的账号提权为超级管理员，或者在电商系统中强行把自己的账户余额修改为 999999，造成难以估量的权限失控和资损。

修复方案：
1. 采用严格的数据传输对象或白名单映射：后端绝不能把前端传来的 JSON 直接反序列化为底层的数据库实体模型。必须在两者之间增加一个 DTO 层，明确规定哪些字段允许从客户端接收，其余所有非白名单字段一律丢弃。
2. 敏感字段后端锁定：'role'、'admin'等决定系统权限的核心字段，绝不应该在对外暴露的公开接口中被允许接收。这些字段必须在服务端逻辑中由后台系统自动赋予默认值。
