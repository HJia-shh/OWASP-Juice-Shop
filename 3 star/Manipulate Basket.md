漏洞名称：操纵他人购物车 / 越权写入与 JSON 参数污染

1. 挑战概述
漏洞类别：业务逻辑缺陷 / JSON 参数污染导致越权

挑战目标：绕过后端的购物车归属权校验，利用 JSON 解析差异将商品强行添加到其他用户的购物车中。

2. 漏洞发现线索与复现过程

在电商业务逻辑中，如果“添加商品到购物车”的 API 接口允许前端自由传递“购物车 ID”，并且后端没有与当前登录用户的会话凭证进行严格绑定，就会产生越权写入漏洞。

  1. 加入一个商品进购物车，同时使用burp suite抓包
  2. 在 Burp Suite 中，修改 `BasketId` 参数。将其修改为其他用户的购物车编号。

3. 实战危害与加固建议
实战危害展示：在真实的电商和支付系统中，参数污染（HPP/JSON Pollution）经常被用来绕过 WAF 或鉴权防护。不仅是操纵购物车，黑客可以利用这种手法在转账接口传入两个收款账户，或者在修改密码接口传入两个用户 ID，导致系统鉴权形同虚设，进而引发大规模的恶意订单生成、库存锁定甚至资金盗刷。

修复方案：
1. 统一 JSON 解析标准与严格校验：在 Web 框架和 API 网关层，必须强制采用严格的 JSON 解析策略。一旦检测到请求体中存在重复的键名，应立即拒绝该请求，绝不能采取“默认覆盖”的宽容策略。
2. 废弃前端身份凭据依赖：最根本的修复方案依然是遵循“服务端绝对信任”原则。在“加入购物车”等敏感业务接口中，服务端不应从 JSON Body 中读取任何形式的 `BasketId` 或 `UserId` 参数，而是直接从当前建立安全会话的 JWT Token 或 Session 中提取用户唯一标识，并在后端执行数据库关联。
