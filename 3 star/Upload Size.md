漏洞名称：文件上传大小限制绕过 / 前端校验失效

1. 挑战概述
漏洞类别：不当的输入验证 / 拒绝服务

挑战目标：绕过系统对上传文件的大小限制，成功向服务器上传一个超过最大允许体积的文件。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，开发者往往为了提升用户体验，在前端使用 JavaScript 对上传文件的类型和大小进行快速校验。但“前端校验形同虚设”，如果后端接口不进行二次兜底校验，攻击者就可以通过抓包改包轻松绕过。

3. 实战危害与加固建议
实战危害展示：在真实的 SRC挖掘中，这种漏洞被称为“存储耗尽型 DoS”。攻击者可以编写 Python 自动化脚本，绕过前端校验，每秒向服务器发送数十个几百兆甚至几 GB 的垃圾文件。这不仅会瞬间塞满目标服务器的磁盘导致服务崩溃，还会给部署在云端的企业带来极其高昂的流量费和存储费用。

修复方案：
1. 强制后端校验：永远不要信任客户端的数据。后端接收文件上传的 API 接口必须在内存中实时校验 `Content-Length` 和实际读取到的字节流大小，一旦超过预设阈值，立即抛出异常并丢弃数据。
2. 网关/中间件层阻断：这是最高效的防御手段。不要让超大文件进入业务代码层，直接在 Nginx 等反向代理或 WAF 上配置 `client_max_body_size` 参数。如果请求体超过限制，网关会直接返回 413 Payload Too Large，从网络接入层切断攻击。
