漏洞名称：伪造用户反馈 / 越权写入

1. 挑战概述
漏洞类别：访问控制缺陷 / 不安全的直接对象引用
挑战目标：以别人的用户名发布一些反馈。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，如果后端接口在执行“创建”或“写入”操作时，盲目信任了前端传递过来的用户 ID，而没有去校验真实登录的会话凭证，就会产生极其危险的越权写入漏洞。

3. 实战危害与加固建议
实战危害展示：越权写入是企业级业务中最忌讳的漏洞之一。如果接口允许客户端直接指定 `UserId`，黑客不仅可以冒充管理员发布虚假公告、恶意带节奏，在电商或金融系统中，更可以利用该漏洞“替别人下单”、“替别人转账”或者“修改别人的收货地址”，直接导致严重的资金损失和业务混乱。

修复方案：
1. 废弃前端身份传参：在进行任何涉及用户归属权的数据写入操作时，绝不允许前端在请求体或 URL 参数中传递代表身份的 `UserId` 字段。
2. 服务端 Token 绝对信任原则：后端业务逻辑必须且只能从当前 HTTP 请求头的会话凭证中解析出真实登录用户的 `UserId`，并将这个提取出的真实 ID 强制绑定到即将落盘的数据上。
