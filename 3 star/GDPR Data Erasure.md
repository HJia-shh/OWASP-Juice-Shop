3. 实战危害与加固建议
实战危害展示：这种“合规性漏洞”在实战中非常多见。企业以为做个软删除就万事大吉，但这不仅违反了 GDPR 隐私法案中“彻底物理擦除”的法律要求，还会留下大量无人认领的僵尸账号。一旦这些账号的哈希密码被破解或通过 SQL 注入被接管，黑客就能以此为跳板，长期在内网潜伏，而管理员在日志中根本查不到这些“已经注销的人”。

修复方案：
1. 严格落实物理删除机制：当用户明确行使 GDPR 擦除权时，后台必须设计定时任务或级联删除脚本，将该用户在所有业务表中的敏感字段彻底执行 `DELETE` 物理擦除，或用不可逆的脱敏乱码完全覆盖。
2. 隔离冻结账户登录态：如果业务需要保留数据流水，则必须在登录验证接口的第一道关卡强制增加校验逻辑：`IF user.is_deleted == true THEN return "Account Deactivated"`，彻底阻断僵尸账户的登入可能。
