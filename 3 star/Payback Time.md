漏洞类别：业务逻辑缺陷 / 不当的输入验证

2. 漏洞发现线索与复现过程

3. 实战危害与加固建议
实战危害展示：这种支付逻辑漏洞对电商平台是致命的。黑客可以利用“正数高价值商品 + 负数低价值商品”的组合对冲账单，实现 0 元白嫖实物商品；或者直接利用巨额负数订单向数字钱包疯狂“反向刷钱”，随后提现走人。在实际攻防演练中，一旦发现这种漏洞，通常直接定级为最高危的严重漏洞。

修复方案：
1. 强制后端的类型与边界校验：前端的 UI 限制毫无安全意义。后端的业务接口必须在控制器层引入严格的输入验证器，强制要求 `quantity` 字段必须为正整数，严禁接收负数、零、浮点数或特殊字符。
2. 采用无符号数据类型：在底层数据库设计时，针对金额、数量、库存等天然不可能为负数的字段，一旦应用层试图写入负数，数据库引擎将直接报错拦截，形成最后一道防线。
3. 也应避免用户把3改成2这种情况，所以后端必须校验用户的cookies，确保前后端总价一致
