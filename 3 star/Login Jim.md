漏洞名称：指定账户接管 / 针对性 SQL 注入

1. 挑战概述
漏洞类别：注入漏洞 / 身份验证破坏

挑战目标：在不知道真实密码的情况下，利用 SQL 注入漏洞，精准接管并登录Jim的账号。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，' OR 1=1--往往只能登录系统默认的第一个账户。但如果我们需要针对特定高管或财务人员进行“精准钓鱼”或账号接管，就需要使用针对性 SQL 注入。

1. 确定邮箱：jim@juice-sh.op。（可以从之前的administer页面中确定，也可以从商品评价中确定）
2. 构造 Payload：在底层 SQL 语句 SELECT * FROM Users WHERE email = '$email' AND password = '$password' 的逻辑下，我们只针对目标邮箱进行闭合并注释后续密码校验。
3. 输入 Payload：jim@juice-sh.op' --
4. 随便输入密码即可

3. 实战危害与加固建议
实战危害展示：这种针对性 SQL 注入在攻击中非常可怕。攻击者不需要破解密码，只需在社交平台或企业通讯录中搜集到目标员工的邮箱，就能利用该漏洞瞬间接管其权限，窃取特定岗位的机密数据，或以该员工名义在内网发送钓鱼邮件，完成内网横向移动。

修复方案：
1. 彻底根除 SQL 拼接：系统级的防御依然是强制在所有数据库交互层使用参数化查询或安全的 ORM 框架，确保任何包含单引号'或注释符--的输入都只被视为普通文本。
2. 严格的输入白名单过滤：在应用网关或 WAF 层面，对涉及登录凭证的参数执行严格的正则表达式过滤。如果邮箱字段包含 SQL 关键字、空格或特殊符号，应直接阻断该请求并记录告警。
