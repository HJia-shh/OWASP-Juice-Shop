漏洞名称：指定账户接管 / 针对性 SQL 注入

1. 挑战概述
漏洞类别：注入漏洞 / 身份验证破坏
挑战目标：在不知道真实密码的情况下，利用 SQL 注入漏洞，精准接管并登录另一个特定用户的账号。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，针对性 SQL 注入的成功率高度依赖于前期的信息收集。一旦我们掌握了目标用户的身份标识，就能利用后端的 SQL 拼接缺陷直接绕过认证逻辑。

和login jim的操作类似
1. 确定邮箱：bender@juice-sh.op。
2. 构造 Payload：后端执行的验证语句 `SELECT * FROM Users WHERE email = '$email' AND password = '$password'`。
3. 输入 payload：bender@juice-sh.op' --并登入即可

3. 实战危害与加固建议
实战危害展示：这种基于已知信息的精准 SQL 注入是针对企业高管或特权账户的常见攻击手段。攻击者无需进行大规模的暴力破解或引发大量告警日志，只需一次请求即可无声无息地接管核心账号。如果在复杂的企业内网中，该账号还关联了其他系统的 SSO权限，将引发严重的连锁入侵反应。

修复方案：
1. 强制使用参数化查询：杜绝任何形式的 SQL 字符串拼接。必须使用预编译语句，将用户提交的邮箱地址严格作为数据字面量处理，剥离其在 SQL 语法树中的执行能力。
2. 纵深防御：在登录接口部署强健的输入验证。所有作为邮箱提交的数据，必须在网关或后端第一时间通过严格的正则校验，若检测到 '、"、--、# 等潜在的 SQL 注入控制字符，直接抛弃请求并触发 WAF 告警。
