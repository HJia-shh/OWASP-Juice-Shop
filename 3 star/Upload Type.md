漏洞名称：文件上传类型限制绕过 / 前端校验失效

1. 挑战概述
漏洞类别：不当的输入验证 / 任意文件上传

挑战目标：绕过系统只允许上传 PDF 或 ZIP 文件的限制，成功向服务器上传一个不属于这两种后缀名的任意文件。

2. 漏洞发现线索与复现过程

在 Web 开发中，程序员通常只在前端 HTML 的 `<input type="file" accept=".pdf, .zip">` 中限制文件类型，或者在前端 JS 中进行后缀检查。这种“只防君子不防黑客”的前端校验，在 Burp Suite 面前相当于完全透明。

3. 实战危害与加固建议
实战危害展示：文件上传类型绕过是极度致命的漏洞。黑客可以通过抓包，将包含恶意代码的图片木马伪装成合法请求，并将后缀篡改为 `.php`、`.jsp` 或 `.asp`。一旦文件落盘且被 Web 容器解析执行，黑客将直接获得服务器的 Shell 权限，导致核心数据库被窃取、内网被全面渗透。

修复方案：
1. 服务端严格白名单校验：绝对不能信任前端的格式限制，也绝不能只校验 HTTP 头中的 `Content-Type`。必须在后端代码中，提取上传文件名的后缀，并与严格的“白名单”进行比对
2. 文件签名深度校验：即便后缀名合法，后端也必须读取文件头的前几个字节，确认其真实文件格式。例如 PDF 的文件头必须是 `%PDF-`，以此防止黑客将恶意脚本重命名为 `.pdf` 绕过检查。
3. 上传目录降权与重命名：所有用户上传的文件，落盘时必须使用随机字符串进行重命名，且上传目录必须取消“脚本执行权限”，确保即使漏放了木马文件，服务器也只会将其当成普通文本下载，而不会解析执行。
