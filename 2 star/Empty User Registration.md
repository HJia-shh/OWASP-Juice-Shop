漏洞名称：空用户注册 / 客户端验证绕过

1. 挑战概述
漏洞类别：业务逻辑缺陷
挑战目标：绕过前端表的非空限制，成功向后端 API 提交并创建一个关键字段为空的用户账号。

2. 漏洞发现线索与复现过程

在 Web 安全测试中，前端的输入框非空限制、格式校验仅仅是为了提升用户体验。如果后端 API 缺乏严格的判空拦截，攻击者完全可以通过审查元素或抓包改包轻松绕过。

3. 漏洞危害与加固建议
实战危害展示：如果后端 API 长期缺乏对必填字段的 `null` 或空字符串校验，攻击者可以编写自动化脚本，瞬间向系统灌入成千上万个“全空”的垃圾账号。这不仅会污染数据库、造成业务数据混乱，更严重的是，当后端其他模块在读取这些空用户对象时，极易因未做防错处理而抛出“空指针异常”，从而引发服务器宕机

修复方案：
1. 服务端强制非空校验：绝不能依赖前端的 `required` 限制。后端 API 在接收到注册请求的 JSON 数据后，必须在业务逻辑层逐一校验核心字段是否为空、是否符合长度和类型规范。一旦发现空值直接返回 `400 Bad Request`。
2. 数据库字段约束：在设计数据库表结构时，必须对关键字段（如 `email`、`password`）显式添加 `NOT NULL` 约束。这是防止脏数据入库的最后一道硬核防线。
