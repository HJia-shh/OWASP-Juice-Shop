漏洞名称：废弃接口未下线

1. 挑战概述
漏洞类别：安全配置错误 / 攻击面管理缺陷
挑战目标：找到并利用系统为了兼容老版本而残留在后端代码中的废弃接口，成功完成特定数据请求。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，如果开发团队在迭代升级时只是“在前端删掉了入口”，却把后端旧版本的 API 代码原封不动地保留在服务器上，就会形成废弃接口漏洞。

3. 漏洞危害与加固建议
实战危害展示：废弃接口是黑客进行“撞库”和“越权”的温床。由于现代安全团队的防御重心通常放在最新版本的主干 API 上，这些无人看管的老旧接口往往存在未修补的高危漏洞。攻击者一旦通过资产测绘发现它们，就能轻松绕过新版系统的安全风控。

修复方案：
1. 严格的生命周期管理：当决定废弃某一代 API 时，不能仅在前端做隐藏。必须在后端网关或路由层配置明确的下线时间表，到期后直接从服务器代码库中彻底删除该路由，严禁长期保留“僵尸接口”。
2. 全流量资产清点：安全团队应定期使用自动化资产发现工具对全网对外暴露的 API 进行盘点，识别并封堵所有未授权、无备案或处于 Deprecated 状态的隐藏接口。
