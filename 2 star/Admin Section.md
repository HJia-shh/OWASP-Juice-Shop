漏洞名称：管理员后台未授权访问

1. 挑战概述
漏洞类别：访问控制缺陷
挑战目标：在没有直接导航链接的情况下，找到并成功访问专属于商店管理员的后台管理页面。

2. 漏洞发现线索与复现过程

在 Web 渗透测试中，基于“隐藏”的安全是极其不可靠的。前端应用通常会在 JavaScript 源码中暴露所有页面的路由表。

1. 需要寻找隐藏的管理员页面路径。
2. 打开inspect里的debugger在代码中全局搜索关键词 `admin`
3. 发现了一条敏感路径配置：path: "administration"

4. 在 URL 尾部手动拼接该路径：http://127.0.0.1:3000/#/administration

5. 页面成功跳转到了管理后台，页面上直接展示了全站所有注册用户的列表以及客户反馈信息。

3. 漏洞危害与加固建议
实战危害展示：这种典型的“强制浏览”越权漏洞在实战中极为致命。如果攻击者通过目录扫描或前端源码审计猜到了后台管理地址，且系统没有做严格的权限校验，攻击者就能直接越权查看全站敏感数据，甚至执行吊销账号、修改价格等高危特权操作。

修复方案：
1. 前端路由守卫：在前端框架中，必须配置路由守卫机制。当用户尝试访问 `/administration` 时，前端需检查当前用户的身份 Token 中是否包含 role: 'admin'，如果不包含，直接重定向回首页。
2. 至于Token有伪造的方法，后面有相对应的挑战
3. 后端接口鉴权：前端的阻拦是可以被抓包绕过的，真正的防御必须在后端 API 实施。所有负责拉取后台数据的 API 接口，必须在控制器层强制校验请求头中的 Token 身份和权限等级。非管理员调用接口一律返回 403 Forbidden。
