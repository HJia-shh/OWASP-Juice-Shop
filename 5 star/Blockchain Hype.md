漏洞名称：隐藏的区块链 ICO 页面 / 前端路由泄露与混淆代码审计

1. 挑战概述
漏洞类别：敏感信息泄露 / 隐蔽式安全缺陷

挑战目标：不依靠盲目爆破，通过审查前端应用程序的路由定义机制，突破代码混淆，找出一个隐藏的代币销售Token Sale / ICO页面的确切 URL 并成功访问。

2. 漏洞发现线索与复现过程

在现代单页应用如 Angular、React、Vue中，前端的所有页面路径都会在打包后的 JavaScript 文件中集中定义。即使页面上没有任何链接指向该路由，只要它被打包进了前端代码，攻击者就可以通过源码审计将其提取出来。

3. 实战危害与加固建议
实战危害展示：这种通过审查前端 `app.js` 或 `main.js` 提取隐藏路由的手法是常规且极具破坏性的基操。许多企业会将“未发布的重磅产品页面”、“内部管理员的监控大屏”或者“遗留的测试接口”打包在前端代码中。攻击者提取到这些隐藏路由后，如果后端 API 缺乏相应的权限校验，就可以直接进行越权访问或信息窃取。

修复方案：
1. 摒弃隐蔽式安全：绝不能将“隐藏 URL”作为访问控制的手段。URL 本身是公开透明的，前端路由的混淆也只能防君子防不住专业黑客。
2. 强制的服务端权限校验：页面的访问权限和对应 API 的数据获取，必须在后端服务器进行严格的权限拦截。如果普通用户访问了管理员专属的隐藏路由，后端 API 应直接拒绝下发数据并返回 403 Forbidden。
3. 动态路由加载：对于高权限的敏感页面和测试组件，不应将其硬编码打包进全局的普通用户前端代码包中。应结合权限系统，在用户成功验证为高权限身份后，再由服务端下发对应的敏感前端组件包。
