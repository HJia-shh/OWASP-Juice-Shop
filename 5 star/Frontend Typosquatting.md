漏洞名称：前端拼写劫持 / 软件供应链投毒

1. 挑战概述
漏洞类别：软件供应链安全 / 恶意组件引入

挑战目标：找出一个当前正被前端应用加载和使用的“拼写劫持”恶意依赖包，并将其报告给官方。

2. 漏洞发现线索与复现过程

我通过搜索资料发现在针对前端架构的渗透测试中，熟知框架的默认构建产物是进行信息收集的高阶技巧。很多框架在打包时会自动暴露前端软件物料清单，这为排查供应链投毒提供了绝佳的情报。

3. 实战危害与加固建议
实战危害展示：前端供应链投毒的实战杀伤力极强且隐蔽。黑客在 npm 注册了 `anuglar2-qrcode` 并注入恶意代码。一旦开发人员手滑敲错名字并执行了 `npm install`，恶意组件就会随着 Angular 的编译被打包进 `vendor.js` 中，下发给所有访问网站的用户。黑客可以直接在前端执行键盘记录、静默窃取用户的 JWT Token 或拦截支付表单，而企业的后端 WAF 对这种“合法引入”的前端代码几乎毫无察觉。

修复方案：
1. 抹除默认构建产物暴露：在 CI/CD 发布流水线中，应配置在推送到生产服务器前，自动删除 `3rdpartylicenses.txt` 等会暴露系统前端完整 SBOM 的默认文件。
2. 自动化 SCA 扫描：在流水线中部署 Snyk 等软件成分分析工具，强制拦截已知存在投毒行为的恶意包。
3. 部署内容安全策略：在 HTTP 响应头中配置严格的 CSP 策略，禁止页面向未知的外部黑客服务器发起网络请求，从而阻断前端恶意代码的数据外发窃取。
