漏洞名称：供应链攻击 / 开发环境凭据窃取风险

1. 挑战概述
漏洞类别：软件供应链安全 / 恶意组件引入

挑战目标：调查系统所使用的开发依赖项，找出一个历史上曾遭受过供应链攻击、并专门窃取开发者凭据的第三方库，在“客户反馈”页面将该事件的官方原始报告 URL 或 CVE 提交给开发团队。

2. 漏洞发现线索与复现过程

在现代软件开发中，黑客的攻击目标往往不再局限于生产环境的服务器，而是直接瞄准了开发者的笔记本电脑。如果开发工具链被植入了恶意代码，黑客就能直接窃取开发者本地的 NPM Token、SSH 私钥或云厂商 API Key。

1. 依旧是package.json.bak文件

3. 实战危害与加固建议
实战危害展示：
这是高级持续性威胁极其青睐的“降维打击”手法。通过感染一个看似无害的开发辅助工具，黑客可以横向感染成千上万名开发者的电脑。一旦窃取了高权限开发者的发布 Token，黑客就可以伪造官方身份，向更多核心组件投毒，造成波及全球的级联性灾难。

修复方案：
1. 强制启用开发者多因素认证：企业必须要求所有在内网或外网发布代码、推送 npm/PyPI 包的开发者，强制开启 2FA，彻底斩断因密码泄露或基础 Token 被窃取的投毒路径。
2. 锁定依赖树与哈希校验：在项目中使用 `package-lock.json`、`yarn.lock` 并结合严格的哈希完整性校验。确保 CI/CD 构建环境下载的依赖包哈希值，与开发环境初次引入时绝对一致。
3. 隔离开发与执行环境：推广使用沙盒化的开发环境，防止本地代码库中的安装脚本拥有读取全局 `.ssh` 或环境变量的越权能力。
