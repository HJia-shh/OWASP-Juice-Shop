漏洞名称：暴露的监控指标

1. 挑战概述
漏洞类别：安全配置错误 / 信息泄露
挑战目标：找到并访问系统向监控工具（Prometheus）暴露的内部运行指标数据接口。

2. 漏洞发现线索与复现过程

在云原生应用和微服务架构中，系统通常会保留特定的标准接口供后台监控系统抓取数据。我们可以通过目录猜解来寻找这些端点。

  1. 尝试在浏览器地址栏中访问常见的监控端点路径，如 `/health`、`/status` 、`/metrics`。
  2. 发现有/metrics目录
  3. 在浏览器中输入 `http://192.168.100.109:3000/metrics`

  4. 页面成功加载，并返回了大量数据。
5. 在页面数据中，可以清晰地看到服务器当前的 CPU 消耗 (process_cpu_user_seconds_total)、内存占用以及各个 HTTP 接口的实时请求统计。

3. 漏洞危害与加固建议
实战危害展示：暴露的监控指标虽然不会直接导致服务器被控制，但会向攻击者泄露极具价值的业务情报。黑客可以通过持续刷新接口，精确计算出网站的真实活跃用户量、高峰期时段，甚至通过监控内存或响应时间指标来辅助判断“拒绝服务攻击”是否奏效。

修复方案：
1. 端口与网络隔离：监控接口绝对不应与对外服务的业务端口（如 3000、80、443）混用。应将其绑定到仅内网可访问的独立管理端口。
2. 强制访问控制：如果必须在同一个端口对外暴露，必须在应用层拦截 `/metrics` 路径，强制要求使用强密码认证或仅允许指定的内部监控白名单 IP 访问。
