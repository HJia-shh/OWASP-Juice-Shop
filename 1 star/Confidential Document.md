漏洞名称：敏感机密文件泄露 (Confidential Document)

1. 挑战概述
漏洞类别：敏感信息泄露 / 目录浏览配置不当

挑战目标：在网站目录中找到并访问一个本不该对外公开的商业机密文件。

2. 漏洞发现线索与复现过程

在Privacy Policy里我提到了一种方法，是目录爆破。我们对他进行目录爆破发现/ftp

1. 尝试访：`http://192.168.100.109:3000/ftp` 
2. 页面没有返回 404 或 403，而是直接列出了该目录下的所有文件结构。这说明 Web 服务器存在目录浏览配置缺陷。

3. 漏洞危害与加固建议
实战危害展示：配置不当的目录浏览权限是企业信息泄露的重灾区。除了商业机密，黑客经常通过这种方式下载到网站的源代码备份、数据库配置文件，甚至是存放员工账密的 Excel 文档，从而直接打穿整个内网。

修复方案：
  1. 关闭目录浏览功能：在 Web 服务器配置中强制关闭列目录权限。例如，在 Nginx 中设置 `autoindex off;`，在 Apache 中设置 `Options -Indexes`。
  2. 核心文件隔离：机密商业文档绝对不应存放在 Web 根目录下。必须将其转移到内网专用的文档管理系统，或存放于 Web 服务器无法直接访问的绝对路径中。
  3. 强制访问控制：如果业务确实需要对外提供文件下载目录，必须在下载接口处实施强身份认证与权限鉴定。
