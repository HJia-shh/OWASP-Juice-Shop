   漏洞类别：业务逻辑缺陷

2. 漏洞发现线索与复现过程

识别机器人交互逻辑边界
现代客服机器人通常会针对用户的辱骂、无意义字符或无法识别的指令设置统一的“默认回复”（Fallback response）。如果高频次、连续地触发这种默认回复，缺乏防御机制的机器人可能会进入异常状态。

3. 漏洞危害与加固建议
实战危害展示：表面上看这只是一个彩蛋，但在真实场景中，这种缺乏频控阈值和逻辑逃逸保护的 Chatbot 可能会被攻击者滥用。例如，黑客可以利用脚本疯狂发送消耗算力的对话请求，导致企业调用大模型的 API 费用暴涨；或者通过特定的诱导话术，套取机器人知识库中的内部数据。

修复方案：
1. 对话频控：在后端接口层面限制单一 Session ID 在短时间内的异常对话请求频率，超过阈值则暂时冻结对话或触发人工接管。
2. 收敛异常回复边界：当机器人连续 3-5 次无法理解用户意图时，应直接中止对话流程或转接人工，绝对不能以“抛出内部代码或优惠券”的方式来结束异常。
