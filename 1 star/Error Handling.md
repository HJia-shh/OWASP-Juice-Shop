漏洞名称：报错信息泄露 (Error Handling)

1. 挑战概述
漏洞类别：安全配置错误

挑战目标：引发一个系统错误，迫使服务器返回包含敏感堆栈追踪信息的报错页面。

2. 漏洞发现线索与复现过程

在现实，我们经常通过输入非预期的路径来探测目标系统。

1. 尝试访问一个系统无法解析的非法 API 请求。例如，：`http://127.0.0.1:3000/api/Users`

2. 页面没有返回标准的 404 自定义错误页，而是直接抛出了一个 500 Internal Server Error。

3. 在页面报错信息，系统打印出了极长的一段后端代码堆栈。
   
4. 仔细查看报错堆栈，不仅能清晰看到后端使用的是 Node.js 及其依赖库版本，甚至直接暴露了服务器内部的文件物理绝对路径。

对于报错信息我了解有 400 格式错误，401 未认证，403 禁止访问，405 请求方拒绝，500 服务器内部错误，503 服务器不可用等。

3. 漏洞危害与加固建议

现实中：报错堆栈泄露是攻击者进行“信息收集”的绝佳跳板。黑客可以通过报错精准得知后端使用的编程语言、框架版本、数据库类型以及服务器目录结构，从而针对性地寻找特定版本的已知 CVE 漏洞进行精准打击。

修复方案：
1. 统一异常接管：在后端代码全局配置错误处理中间件。
2. 屏蔽堆栈信息：在生产环境中，绝对禁止向前端返回详细的 Stack Trace。发生错误时，前端统一返回友好的自定义状态页（如“系统繁忙，请稍后再试”），并将详数据记录到日志文件中供排查。
